# C04 보안 기본선 (KMS, CloudTrail, 감사 버킷, 사람용 역할)

## 목표

법규 요구(접속기록 2년 보관·위변조 방지, 암호화, 최소 권한)를 이후 모든 스택이 기대는 기반으로 먼저 만든다.

## 산출물

| 리소스 | 설정 | 근거 |
| --- | --- | --- |
| KMS `lake`, `pii`, `logs` | 용도별 분리, 자동 회전 | 키 정책·감사 범위를 용도별로 나눈다 |
| 감사 버킷 | 객체 잠금 GOVERNANCE 730일, KMS | 안전성 확보조치 기준 제8조: 5만 명 이상 처리 시 접속기록 2년 이상, 위·변조 방지 |
| CloudTrail | 관리 이벤트 전부 + silver/gold/kl-raw 객체 데이터 이벤트, 로그 무결성 검증 | 누가 어떤 개인정보 객체를 읽었는지. digest 파일로 위·변조 여부 증명 |
| SNS `alerts` | KMS 암호화, 이메일 구독 | 모든 알람의 공통 목적지 |
| Secrets `pii/hmac-key` | 틀만 Terraform, 값은 `scripts/init_pii_secret.py` | 키가 state에 평문으로 남지 않게 |
| IAM 역할 analyst·finance·engineer | MFA 필수, Athena·Glue 읽기·`lakeformation:GetDataAccess` | 데이터 권한은 Lake Formation이 준다(P1-12) |
| Session Manager 설정 | 세션 로그를 감사 버킷 `ssm-sessions/`에 | 운영자 접속기록 |

## 적용

```bash
make init STACK=20-security && make plan STACK=20-security && make apply STACK=20-security
python scripts/init_pii_secret.py --env dev
```

## 검증

```bash
aws cloudtrail get-trail-status --name danbi-dev-trail          # IsLogging: true
aws cloudtrail validate-logs --trail-arn <trail-arn> --start-time 2026-10-30T00:00:00Z
aws s3api get-object-lock-configuration --bucket danbi-dev-audit-<계정>
```

- 감사 버킷에서 객체 삭제를 시도하면 `AccessDenied`(보존 기간 중)여야 한다.

## 완료 기준

- `validate-logs`가 "valid"를 보고한다.
- dev 정리 시에는 `s3:BypassGovernanceRetention` 권한이 있는 역할만 삭제할 수 있음을 확인했다(운영은 COMPLIANCE로 바꾼다).
