# P1-04 CDC: Debezium on MSK Connect (MySQL·PostgreSQL·Outbox)

## 목표

운영 DB 의 생성·수정·삭제를 로그 기반으로 수집하고(FR-01), 결제 도메인 이벤트는 Outbox 로 발행한다(FR-02). 커넥터를 지우고 다시 만들어도 같은 위치에서 이어받게 한다(F-01).

## 산출물

| 경로 | 내용 |
| --- | --- |
| `p1/cdc/connectors/*.tftpl` | 커넥터·워커 설정 원본. Terraform `templatefile` 과 CI 린트가 같은 파일을 쓴다 |
| `p1/cdc/lint.py` | 설정 규칙 + "커넥터가 쓸 토픽이 topics.yaml 에 다 있나" 교차 검사 |
| `p1/cdc/signal.py` | 증분 스냅샷 신호(S-C3 전체 재스냅샷, F-03 구간 재수집) |
| `p1/cdc/build_plugin.sh` | Debezium + Avro 컨버터 + Secrets Manager config provider zip (Maven sha1 검증) |
| `infra/stacks/p1-20-streaming/cdc.tf` | 아티팩트 버킷, 커스텀 플러그인, 워커 설정, 커넥터 2개, 서비스 실행 역할(토픽 접두사 단위 최소 권한) |
| `p1/streaming/topics.yaml` (추가) | Debezium 하트비트 토픽 2개 |

## 설계 포인트

| 결정 | 이유 |
| --- | --- |
| `offset.storage.topic=connect.offsets.cdc` | MSK Connect 기본 오프셋 토픽은 커넥터 ID 에 묶여, 재생성 시 처음부터 다시 스냅샷한다 |
| 암호는 `${secretsmanager:...}` | 커넥터 설정은 콘솔·API 로 누구나 읽는다. 평문이면 유출이다 |
| `snapshot.locking.mode=none` | RDS 는 전역 락이 불가하고, 운영 테이블 락은 장애다. GTID 로 일관성 확보 |
| `decimal.handling.mode=string` | 금액 정밀도 보존. Avro bytes decimal 은 Python 소비자에서 다루기 번거롭다 |
| `tombstones.on.delete=false` | Bronze 는 `op=d` 이벤트로 삭제를 기록한다. 압축 토픽이 아니므로 툼스톤은 잡음 |
| PG `heartbeat.action.query` | 결제 DB 가 한가해도 슬롯 LSN 이 전진 → WAL 누적 방지 |
| Outbox EventRouter + predicate | outbox 테이블 토픽만 `events.payment` 로 라우팅, 키 = payment_key(같은 결제는 같은 파티션) |
| `tasks.max=1`, 워커 1 | binlog·WAL 은 하나의 순서 있는 스트림이라 병렬 이득이 없다 |
| Debezium 2.7 기본 | 3.x 는 Java 17 필요. MSK Connect 3.7.x 런타임 JVM 이 문서에 명시돼 있지 않아 dev 에서 먼저 확인 후 올린다 |

## 적용

```bash
./p1/cdc/build_plugin.sh --upload           # 출력된 plugin_key 를 tfvars 에
echo 'plugin_key = "msk-connect/plugins/danbi-cdc-plugin-2.7.4.zip"' >> infra/envs/dev/p1-20-streaming.tfvars
make plan STACK=p1-20-streaming && make apply STACK=p1-20-streaming
```

> MSK Connect 워커는 Secrets Manager API 를 호출한다. NAT(기본) 또는 인터페이스 엔드포인트(`enable_interface_endpoints`)가 있어야 한다.

## 검증

```bash
aws kafkaconnect list-connectors --query 'connectors[].{n:connectorName,s:connectorState}'
# 소스에서 UPDATE 1건 → 토픽에서 확인 (stream-admin 태스크 또는 ECS Exec)
# F-01: connectors_enabled=false 로 apply(삭제) → 30분 뒤 true → 유실 0 확인(P1-09 대사)
python -m p1.cdc.signal --engine mysql snapshot commerce.order_items   # S-C3
```

## 완료 기준

- 두 커넥터 RUNNING, 각 테이블 토픽과 `events.payment` 에 메시지가 들어온다.
- 커넥터 삭제·재생성 후 재스냅샷 없이 이어받는다(오프셋 토픽 유지 확인).
- `pytest p1/cdc` 가 설정 규칙 위반과 토픽 누락을 잡는다.
