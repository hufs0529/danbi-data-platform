# P1-14 관측성: 데이터 신선도·SLO 알람·대시보드·에러 버짓

## 목표

"새벽 3시에 알림을 받은 사람이 런북만 보고 30분 안에 판단할 수 있는가"를 기준으로, 사용자 영향(증상)에만 알림을 걸고 모든 알림에 런북을 붙인다. SLO 를 숫자로 관리하고 에러 버짓 규칙을 둔다.

## 산출물

| 경로 | 내용 |
| --- | --- |
| `p1/observability/slos.yaml` | **SLO·알림 단일 원본**: SLO 5개(Silver·Bronze·실시간 신선도, Gold 게시 기한, 대사 0건), 증상 알림 6개, 감시 테이블 |
| `p1/observability/monitor.py` | Lambda: Iceberg 메타데이터로 신선도(테이블 스캔 없음), Gold 기한(06:30 KST 경고), 커넥터 상태, 작은 파일 비율 |
| `p1/observability/slo_report.py` | 월간 달성률·에러 버짓(표본 없음 = 나쁨), 소진 시 '기능 작업 중지' |
| `infra/stacks/p1-70-observability` | Lambda(메타데이터만 읽는 최소 권한), 스케줄(5분·매일), YAML → 알람(for_each), Flink 체크포인트 알람, 대시보드 |
| `p1/streaming/realtime/alert_lambda.py` (추가) | DLQ 는 내용을 읽지 않고 건수만 지표로(원문에 개인정보) |

## SLO

| 데이터 제품 | SLI | 목표(30일) | 알림 |
| --- | --- | --- | --- |
| silver.orders | 마지막 커밋 경과 | 시간의 99% ≤ 15분 | 30분 초과 2회 연속 |
| bronze.cdc_events | 마지막 커밋 경과 | 99% ≤ 2분 | 10분 초과 |
| rt.sales_1m | 집계 반영 지연 | 99% ≤ 90초(측정 3분 해상도) | 5분 연속 5분 초과 |
| gold.mart_daily_sales | 게시 시각 | 30일 중 29일 07:00 이전 | 06:30 미게시 |
| gold.recon_pg_settlement | 미설명 차이 | 0건 | 1건 이상 즉시 |

## 설계 포인트

- **신선도는 쿼리가 아니라 메타데이터로.** 5분마다 스캔하면 비용이 들고, 쿼리 실패와 데이터 지연이 구별되지 않는다.
- **측정이 멈춘 것도 장애.** 신선도·커넥터 지표가 안 들어오면 알람(`treat_missing_data = breaching`), 리포트에서도 빈 표본은 '나쁨'.
- **지연은 건수가 아니라 시간으로.** `EstimatedMaxTimeLag`(초). "1만 건 밀림"은 처리량에 따라 1초일 수도 10분일 수도 있다.
- **원인 지표는 알림이 아니라 대시보드.** 브로커 CPU 는 사용자 영향이 아니다. 알림 피로를 줄인다.
- **에러 버짓 정책.** 버짓을 다 쓰면 그 데이터 제품의 기능 작업을 멈추고 안정화한다(리포트에 굵게 표시).
