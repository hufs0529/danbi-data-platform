# C03 VPC·서브넷·라우트 테이블·NACL·엔드포인트

## 목표

P1·P2가 함께 쓰는 네트워크를 3계층(공인·앱·데이터) × 2 AZ로 만들고, 계층 사이 트래픽을 라우팅·NACL·SG 세 겹으로 통제한다.

## 산출물

| 경로 | 내용 |
| --- | --- |
| `infra/modules/network` (+ `tests/network.tftest.hcl`) | VPC, 서브넷, IGW, NAT(none/single/per_az), 라우트 테이블, NACL 규칙, 게이트웨이·인터페이스 엔드포인트, 흐름 로그 |
| `infra/modules/secure_bucket` | 퍼블릭 차단·TLS 강제·암호화·수명 주기·객체 잠금 옵션을 가진 S3 모듈 |
| `infra/modules/ssm_outputs` | 스택 간 값 전달(SSM Parameter Store) |
| `infra/stacks/10-network` | 위 모듈 조합, 흐름 로그 버킷, SSM 출력 |
| `infra/stacks/10-network/sql/vpc_flow_logs.sql` | 흐름 로그 Athena 테이블(파티션 프로젝션) |
| `docs/runbooks/network-debugging.md` | 연결 장애 확인 순서 |

## 설계 요약

- CIDR: 공인 `10.20.0.0/19`, 앱 `10.20.32.0/19`, 데이터 `10.20.64.0/19` (각 AZ에 `/20`)
- 라우트: 공인 → IGW, 앱(AZ별) → NAT, 데이터 → **local만**
- NACL: 공인은 22·3389 명시 거부, 데이터는 앱 계층에서 오는 서비스 포트만 허용, 응답은 임시 포트 1024–65535
- 엔드포인트: S3·DynamoDB 게이트웨이(무료, 앱 라우트 테이블), 인터페이스 12종은 토글
- 기본 보안 그룹은 모든 규칙을 비운다

## 적용

```bash
make init STACK=10-network && make plan STACK=10-network && make apply STACK=10-network
```

## 검증

설계 규칙은 테스트로 고정되어 있다(자격증명 없이 mock provider로 plan).

```bash
cd infra/modules/network && terraform test   # 6개: NAT 모드 3종, 데이터 계층 격리, 22·3389 거부, 엔드포인트 토글
```

적용 후:

```bash
# 라우트: 데이터 서브넷 라우트 테이블에 0.0.0.0/0 이 없어야 한다
aws ec2 describe-route-tables --filters Name=tag:Name,Values=danbi-dev-rt-data \
  --query 'RouteTables[].Routes[].DestinationCidrBlock'

# NACL: 데이터 NACL 인바운드에 0.0.0.0/0 규칙이 없어야 한다
aws ec2 describe-network-acls --filters Name=tag:Name,Values=danbi-dev-nacl-data \
  --query 'NetworkAcls[].Entries[?Egress==`false`].[RuleNumber,CidrBlock,PortRange]'

# SSM 계약 값
aws ssm get-parameters-by-path --path /danbi/dev/network
```

- Reachability Analyzer로 "앱 서브넷의 ENI → 인터넷 게이트웨이"(NAT 경유 성공), "데이터 서브넷 ENI → 인터넷 게이트웨이"(실패)를 확인한다.

## 완료 기준

- 위 검증 3개가 기대대로 나온다.
- `nat_mode=none`으로 바꿔 plan 하면 NAT·EIP·기본 경로만 삭제 대상으로 나온다.
