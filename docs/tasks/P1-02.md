# P1-02 데이터 생성기(상태 기계)와 PG 정산 파일

## 목표

랜덤 행이 아니라 업무 흐름(가입 → 탐색 → 주문 → 승인 → 매입 → 부분취소 → 배송)을 따르는 생성기를 만든다. 장애 훈련과 변경 관리 시나리오를 결함 주입 옵션으로 재현할 수 있어야 한다.

## 산출물

| 경로 | 내용 |
| --- | --- |
| `p1/generator/simulate.py` | 상태 기계. `tick()` = 가상 1초, 결과는 액션 목록(DB 에 쓰지 않음) → seed 로 재현 가능 |
| `p1/generator/actions.py`, `sinks.py` | 액션(Write=트랜잭션, Click, Ddl)과 적용기(MySQL·PostgreSQL·Kafka·메모리) |

| `p1/generator/faults.py` | 결함 주입 손잡이 (`--faults late=0.02,ooo=0.01,dup=0.01,schema_change_at=600`) |
| `p1/generator/Dockerfile` | arm64 이미지(생성기 + 소스 마이그레이션) |
| `contracts/avro/click_event.avsc` | 클릭 이벤트 스키마(enum 대신 string: 심볼 추가가 BACKWARD 비호환이라서) |
| `infra/stacks/p1-10-sources` (추가) | 생성기 ECS 서비스(Fargate Spot, 기본 0대), `db-migrate` RunTask 정의(마스터 암호를 읽는 유일한 주체) |

## 결함 주입 → 시나리오

| 옵션 | 재현하는 것 | 시나리오 |
| --- | --- | --- |
| `late=` | 앱 오프라인 후 최대 2시간 늦은 클릭 전송 | F-05 |
| `dup=` | 같은 클릭 재전송, outbox 이벤트 중복(다른 id, 같은 version) | FR-08 |
| `ooo=` | 매입 웹훅이 승인보다 먼저 도착(상태 역전) | S-B3, FR-08 |
| `hard_delete=` | 배송지 하드 삭제 | Silver 삭제 처리 |
| `schema_change_at=` / `breaking_change_at=` | orders 컬럼 추가 / 금액 컬럼 타입 변경 | S-C1 |
| `null_amount=` | outbox payload 금액 null 급증 | F-08 |
| `settle --faults missing,skew,extra,duplicate,correction,broken_encoding,header_v2` | 정산 파일 문제 전부 | S-B2, F-06 |

## 적용·실행

```bash
docker buildx build --platform linux/arm64 -f p1/generator/Dockerfile \
  -t $(aws ssm get-parameter --name /danbi/dev/platform/ecr_registry --query Parameter.Value --output text)/danbi-dev/generator:$(git rev-parse --short HEAD) --push .
make plan STACK=p1-10-sources && make apply STACK=p1-10-sources   # -var generator_image_tag=<sha>
make db-migrate ENGINE=mysql && make db-migrate ENGINE=postgres
# 첫 실행만 카탈로그 시드
aws ecs run-task ... --overrides '{"containerOverrides":[{"name":"app","command":["p1.generator.cli","run","--seed-catalog","--duration","60"]}]}'
make gen-start            # 이후 계속 생성. make gen-stop 또는 다음 apply 때 0대로 돌아간다
```

로컬에서 DB 없이: `PYTHONPATH=.:libs python -m p1.generator.cli dry-run --seconds 600 --faults late=0.05,ooo=0.05`

## 검증

- 단위 테스트: 같은 seed → 같은 결과, 결제 상태 변경과 outbox 가 같은 트랜잭션, version 단조 증가, 환불 ≤ 결제액, 상태 역전 발생, CP949·TRAILER·마감·정정본
- AWS: `SELECT status, count(*) FROM orders GROUP BY 1`, `SELECT type, count(*) FROM outbox_events GROUP BY 1`

## 완료 기준

- 생성기가 1시간 동안 돌며 오류 없이 주문 약 1,800건과 결제 이벤트를 만든다.
- `settle` 이 CP949 파일을 랜딩 버킷 `pg_settlement/dt=YYYY-MM-DD/` 에 올린다(P1-05 이후).
