# P1-07 Silver 증분 MERGE·SCD2·Iceberg 유지보수 (EMR Serverless)

## 목표

Bronze 변경 로그를 계약대로 해석해 Silver 현재 상태·SCD2 이력·이벤트 테이블을 5~15분 주기로 만든다(FR-05, ADR-06). 같은 구간을 몇 번 처리해도 결과가 같아야 한다(FR-09). 작은 파일·스냅샷·고아 파일을 자동으로 정리한다(F-07).

## 산출물

| 경로 | 내용 |
| --- | --- |
| `p1/batch/transforms.py` | 계약 기반 형 변환(ISO·레거시 KST·일수), 파생 컬럼, 최신 판정(change_seq), MERGE·SCD2·중복 제거 SQL 생성 |
| `p1/batch/jobs/silver_merge.py` | 워터마크 + 겹침 창 증분, 스키마 드리프트 기록·자동 컬럼 추가, 백필 모드(--from/--to) |
| `p1/batch/jobs/maintenance.py` | Bronze 90일 보존(DELETE), 컴팩션, 스냅샷 만료(7일), 고아 파일(3일), 매니페스트 |
| `p1/batch/spark-defaults.json` | Spark·Iceberg 설정 단일 원본(파이썬 잡과 Terraform 이 같이 읽음) |
| `p1/batch/build_spark_jobs.sh` | 진입 스크립트 + 의존 코드 zip |
| `infra/stacks/p1-40-processing/emr.tf` | EMR Serverless(ARM64, 최대 16vCPU, 10분 유휴 정지, 동시 3), 잡 역할, 제출 매개변수 SSM |

## 설계 포인트

| 결정 | 이유 |
| --- | --- |
| 워터마크 = Bronze ingest_ts, 10분 겹침 | Iceberg 커밋은 체크포인트 때 일어나 '지난 시각'의 행이 늦게 보인다. 겹쳐 읽고 MERGE 가드로 흡수 |
| `WHEN MATCHED AND s._src_seq > t._src_seq` | 재시도·재처리·늦게 도착한 옛 변경이 최신 값을 덮지 않는다 |
| 삭제 → `is_deleted` | 운영 하드 삭제도 분석·감사에서는 이력이다. 개인정보 파기는 P1-13 경로 |
| SCD2: 같은 트랜잭션은 마지막 변경만 | 유효 구간 0인 버전 방지 |
| SCD2: 추적 컬럼이 같으면 버전 없음 | 다른 컬럼만 바뀐 변경이 이력을 부풀리지 않는다 |
| 드리프트 컬럼 자동 추가(문자열) | S-C1 "30분 내 Silver 노출". 분류 전에는 분석가 열 필터에 없다(P1-12) |
| merge-on-read | 작은 MERGE 의 쓰기 증폭을 줄인다. 대가로 매일 컴팩션 |
| 백필은 워터마크를 움직이지 않음 | 정기 증분과 섞이지 않는다 |
| 보존은 테이블 연산 | S3 수명 주기 만료는 Iceberg 테이블을 깨뜨린다 |

## 적용·실행

```bash
./p1/batch/build_spark_jobs.sh --upload
echo 'spark_jobs_version = "<sha>"' >> infra/envs/dev/p1-40-processing.tfvars
make plan STACK=p1-40-processing && make apply STACK=p1-40-processing
make spark-job JOB=silver_merge
make spark-job JOB=silver_merge ARGS="--tables silver.orders --from 2026-10-27T00:00:00 --to 2026-10-30T00:00:00"   # 백필
make spark-job JOB=maintenance
```

정기 실행은 MWAA(P1-10)가 맡는다.

## 검증

```sql
-- 멱등: 같은 백필을 두 번 돌린 뒤 행 수·체크섬이 같다
SELECT count(*), sum(total_amount) FROM silver.orders;
-- SCD2: 회원당 current 1개
SELECT member_token, count(*) FROM silver.dim_member_scd2 WHERE is_current GROUP BY 1 HAVING count(*) > 1;  -- 0행
-- 작은 파일 비율(NFR-11)
SELECT count_if(file_size_in_bytes < 32*1024*1024) * 1.0 / count(*) FROM "silver"."orders$files";
```

## 완료 기준

- 단위 테스트(로컬 Spark): 순서 역전·삭제·레거시 시간대·드리프트·SCD2(신규, 같은 트랜잭션, 닫기, 멱등, 비추적 변경)
- 같은 구간 2회 처리 후 Silver 결과 동일, 유지보수 후 작은 파일 비율 ≤ 10%.
