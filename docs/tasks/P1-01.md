# P1-01 소스 DB(RDS MySQL·PostgreSQL)와 CDC 사전 설정

## 목표

단비마켓 주문(MySQL)·결제(PostgreSQL) 운영 DB를 만들고, CDC 가 가능하도록 binlog·WAL 을 설정한다. 운영 DB 관점에서 "CDC 가 운영에 주는 부담"을 설정값으로 통제한다.

## 산출물

| 경로 | 내용 |
| --- | --- |
| `infra/stacks/p1-10-sources` | RDS 2대(db.t4g.micro, 데이터 서브넷), 파라미터 그룹, SG(mysql·postgres·db-clients·msk-clients), 앱 계정 비밀 컨테이너, 매일 자동 정지 스케줄 |
| `p1/sources/sql/` | 스키마(주문 9개 테이블 + 신호 테이블 / 결제 4개 + outbox·신호·하트비트), publication |
| `p1/sources/migrate.py` | 버전·체크섬 기반 마이그레이션, 앱 계정 생성과 암호 회전(Secrets Manager 직접 기록) |
| `scripts/rds_power.py` | 태그 기반 정지·시작(`make pause/resume`) |

## 설계 포인트

| 설정 | 값 | 이유 |
| --- | --- | --- |
| `binlog_format` / `binlog_row_image` | ROW / FULL | 행 단위 before·after. SCD2 와 감사에 필요 |
| `gtid-mode` | ON | 장애 조치 후 같은 위치에서 이어받기(F-02) |
| binlog retention hours | 72 | RDS 기본은 즉시 삭제. 주말 동안 커넥터가 멈춰도 복구 가능(F-03) |
| 백업 보존 | 1일 | 0 이면 RDS MySQL 의 binlog 자체가 꺼진다 |
| `rds.logical_replication` | 1 | pgoutput 논리 복제 |
| `max_slot_wal_keep_size` | 4GB | 슬롯이 WAL 을 무한히 붙잡아 디스크가 차는 것을 막는다. 넘으면 슬롯 무효화 → 재스냅샷(F-03) |
| publication | 수동 생성 | 커넥터에 슈퍼유저를 주지 않고, 대상 테이블을 명시 |
| 하트비트 테이블 | 있음 | 결제 DB 가 한가할 때도 슬롯이 전진하도록 |
| debezium 계정 | LOCK TABLES 없음 | `snapshot.locking.mode=none` + GTID 로 락 없이 스냅샷 |

## 적용

```bash
make init STACK=p1-10-sources && make plan STACK=p1-10-sources && make apply STACK=p1-10-sources
# 파라미터 그룹의 pending-reboot 값(GTID, logical_replication)을 반영
aws rds reboot-db-instance --db-instance-identifier danbi-dev-mysql
aws rds reboot-db-instance --db-instance-identifier danbi-dev-postgres

# 운영 EC2 경유 포트 포워딩 후 마이그레이션 + 계정 생성
aws ssm start-session --target "$(aws ssm get-parameter --name /danbi/dev/platform/ops_instance_id --query Parameter.Value --output text)" \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters host=$(aws ssm get-parameter --name /danbi/dev/p1/sources/mysql_endpoint --query Parameter.Value --output text),portNumber=3306,localPortNumber=13306
python -m p1.sources.migrate --engine mysql --host 127.0.0.1 --port 13306 --bootstrap-users
python -m p1.sources.migrate --engine postgres --host 127.0.0.1 --port 15432 --bootstrap-users
```

> DB SG 는 `sg-db-clients` 와 운영 EC2 의 `sg-ops` 에서 오는 연결만 받는다. 노트북에서 DB 로 직접 가는 경로는 없다.

## 검증

```sql
-- MySQL
SHOW VARIABLES LIKE 'gtid_mode';               -- ON
CALL mysql.rds_show_configuration;              -- binlog retention hours = 72
SHOW GRANTS FOR 'debezium'@'%';
-- PostgreSQL
SHOW wal_level;                                  -- logical
SELECT * FROM pg_publication_tables WHERE pubname = 'dbz_publication';
```

## 완료 기준

- 두 DB 에 마이그레이션이 적용되고 `schema_migrations` 에 체크섬이 남는다.
- 앱 계정 6개의 비밀이 Secrets Manager 에 있고, Terraform state 에는 암호가 없다.
- `python scripts/rds_power.py stop` 후 다음 날 02:00 KST 스케줄이 정지 상태를 유지한다.
