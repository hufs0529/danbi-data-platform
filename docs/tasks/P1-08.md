# P1-08 Gold 모델(dbt-athena)과 Write-Audit-Publish

## 목표

Silver 에서 재무·마케팅이 쓰는 Gold 를 만든다. **검증을 통과한 결과만** 분석가에게 보이게 하고(FR-15, F-08), 지표 정의를 한 곳에 둔다(FR-16, S-G5).

## WAP 흐름

```
dbt build (gold_audit 에 쓰고 테스트) ── 실패 하나라도 → 게시 안 함, 기존 gold 유지, 알림
        │ 전부 통과
        ▼
publish_gold (EMR): 스키마 비교 → INSERT OVERWRITE gold.x (Iceberg 커밋 1회) → publish_log(이전 스냅샷)
        ▼
문제가 나중에 발견되면: publish_gold --rollback --models x  (rollback_to_snapshot)
```

Athena 는 Iceberg 테이블을 `INSERT OVERWRITE` 로 원자적으로 교체하지 못해, 게시만 Spark 로 한다. 권한도 나뉜다: dbt 역할은 gold 에 쓸 수 없고, 분석가는 gold_audit 를 볼 수 없다.

## 설계 포인트

- **할인 배분은 원 단위까지 맞춘다.** 비율 배분 후 절사 차액을 마지막 아이템에 몰아준다. 테스트로 고정.
- **취소 기준 두 가지.** 발생일 기준(재무, 기본)과 원주문일 기준(프로모션 분석). 둘을 같은 이름으로 부르지 않는다.
- **지표 버전.** 정의를 바꾸면 `metric_version` 을 올리고 마트에 함께 싣는다. 대시보드가 버전을 표시한다.
- **dim_member 에 암호문이 없다.** 복호화 대상 자체를 Gold 에 두지 않는다.
- **`on_schema_change: fail`.** 스키마가 바뀌면 조용히 넘어가지 않는다.

## 실행

```bash
docker buildx build --platform linux/arm64 -f p1/dbt/docker/Dockerfile -t $ECR/danbi-dev/dbt-runner:<sha> --push .
make apply STACK=p1-40-processing   # dbt_image_tag=<sha>
# 수동 실행(평소에는 MWAA)
aws ecs run-task --task-definition danbi-dev-dbt-runner ... --overrides '{"containerOverrides":[{"name":"app","command":["build","--select","tag:publish"],"environment":[{"name":"DBT_RUN_ID","value":"r1"}]}]}'
make spark-job JOB=publish_gold ARGS="--run-results s3://<artifacts>/dbt/runs/r1/run_results.json"
```

## 검증

- 로컬: `cd p1/dbt && DBT_PROFILES_DIR=. dbt parse` (모델 7, 테스트 24, 지표 5)
- F-08: 생성기 `--faults null_amount=0.3` → `null_ratio_below` 실패 → 게시 안 됨, gold 스냅샷 그대로
- `SELECT * FROM ops.publish_log ORDER BY published_at DESC`

## 완료 기준

- 모든 테스트 통과 시에만 gold 가 바뀌고, 한 번의 게시가 한 번의 스냅샷이다.
- Gold 순매출 = Silver 재계산(대사 2단계) 테스트 통과.
