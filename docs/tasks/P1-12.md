# P1-12 데이터 계약 거버넌스와 Lake Formation 접근 제어

## 목표

"누가 어떤 컬럼을 볼 수 있나"를 코드로 정하고(FR-12, NFR-09), 계약 위반·비호환 변경·분류 누락을 **배포 전에** CI 에서 막는다(FR-10, NFR-12, S-C1). 신규 분석가의 기간제 권한(S-G2)과 비상 접근을 절차로 만든다.

## 권한 모델

| 주체 | 범위(태그 식) | 못 보는 것 |
| --- | --- | --- |
| 분석가 | layer=gold ∧ classification∈{public, internal, personal_generalized} | 토큰·암호문 컬럼, gold_audit, silver, dim_member 전체(→ 동의 회원 행 필터로만) |
| 재무 | layer=gold ∧ classification∈{public, internal} | 위 + 일반화 값 |
| 엔지니어 | layer∈{silver, gold, ops} ∧ 암호문·restricted 제외 | 암호문 |
| 파이프라인(EMR·dbt·대사·MWAA) | 위치 접근 + DB·테이블 ALL(이름 기반) | — (쓰기 주체) |
| break-glass | silver·gold 전체 + 회원 키 복호화 | — (MFA·누구인지 필수, 1시간, 사용 즉시 알림) |

## 설계 포인트

- **컬럼 태그가 테이블 태그를 이긴다.** 테이블은 internal, member_token 컬럼만 personal_token → 분석가 SELECT 결과에서 그 컬럼이 자동으로 빠진다. 새 모델에 메타가 없어도 `*_token` 이름이면 personal_token 으로 태깅(안전망).
- **소스 컬럼 전수 매핑.** 운영팀이 새 컬럼을 추가하면 CI 가 "계약에도 unmapped 에도 없다"로 실패한다. 개인정보가 조용히 레이크로 흘러드는 가장 흔한 경로를 막는다.
- **동의 범위 = 행 필터.** 마케팅 분석은 마케팅 수신 동의 회원만 대상이다(개인정보 보호법 제18조 목적 외 이용 제한). 정책을 문서가 아니라 LF 행 필터로 강제한다.
- **LF 는 쓰기를 통제하지 않는다.** 쓰기 권한은 파이프라인 역할의 IAM 으로만 존재하고, 사람 역할에는 레이크 버킷 S3 권한이 없다.
- **접근 요청은 PR.** 부여·변경·말소 이력이 Git·CloudTrail 에 남고(안전성 확보조치 기준), 만료는 매일 자동 반영된다.

## 적용 순서

```bash
make apply STACK=p1-60-governance
python -m p1.governance.lf_sync revoke-iam-allowed        # LF 전환(1회). 그 전에 파이프라인 권한이 적용돼 있어야 한다
python -m p1.governance.lf_sync apply --manifest s3://<artifacts>/dbt/runs/<최근>/manifest.json
# gold.dim_member 게시 후
make plan STACK=p1-60-governance  # -var create_data_filters=true
```

## 검증

- 분석가 역할로 `SELECT * FROM gold.fct_order_items LIMIT 1` → member_token 컬럼 없음, `SELECT * FROM silver.orders` → 권한 오류(NFR-09)
- `SELECT count(*) FROM gold.dim_member` (분석가) = 동의 회원 수
- 계약에서 컬럼 타입을 바꾼 PR → `contracts.compat` 실패 / 소스 DDL 에 컬럼 추가 → `contracts.governance` 실패

## 완료 기준

- 역할×테이블×컬럼 기대값 매트릭스(위 표)가 실제 쿼리 결과와 일치, 분석가의 PII 평문 조회 0건.
