# P1-06 Bronze 수집 잡(Managed Flink, PyFlink)과 수집 시점 PII 처리

## 목표

CDC·Outbox·클릭 토픽을 하나의 Flink 잡으로 읽어 Iceberg Bronze 에 쌓는다(FR-04). **Bronze 부터 평문 개인정보가 없게** 수집 시점에 토큰화·암호화·마스킹·일반화하고(PII 보호 2단계), 해석할 수 없는 메시지는 DLQ 로 격리한다(F-04).

## 설계 포인트

- **값을 raw 바이트로 받고 UDTF 에서 해석한다.** 포맷 역직렬화기에 맡기면 독약 메시지 하나가 잡 전체를 멈춘다. 여기서는 실패 행을 `ok=false` 로 내보내 DLQ 로 보낸다.
- **같은 회원 = 같은 토큰.** `member_id` 는 모든 소스에서 `token:member` 로 같아 조인이 유지된다. CDC 키(key_json)에도 같은 정책을 적용한다.
- **crypto-shredding.** 이름·주소는 회원별 데이터 키로 암호화한다. 탈퇴 시 키를 폐기하면(묘비) Bronze·스냅샷·백업에 남은 암호문까지 읽을 수 없다. 키 테이블에 PITR 을 켜지 않는 이유는 35일간 키 복구가 가능해 파기가 끝나지 않기 때문이다.
- **AAD 에 (회원 토큰, 필드명).** 암호문을 다른 회원·필드로 옮겨 붙이면 복호화가 실패한다.
- **정책은 빌드 시점에 고정.** 계약이 바뀌면 앱을 다시 배포해야 반영된다 → 정책 변경 이력 = 배포 이력.
- **체크포인트 15초.** Iceberg 커밋 주기 = Bronze 지연의 하한(NFR-01 p95 ≤ 30초). 작은 파일은 P1-07 컴팩션이 정리한다.
- **오토스케일 끔.** 재시작마다 체크포인트·재처리 지연이 생긴다. 부하 테스트(NFR-06)로 병렬도를 정한다.

## 검증

```sql
SELECT table_name, op, count(*) FROM bronze.cdc_events WHERE ingest_ts > now() - interval '10' minute GROUP BY 1, 2;
-- 평문이 없는지: 이메일·전화 패턴이 0 건이어야 한다
SELECT count(*) FROM bronze.cdc_events WHERE regexp_like(after_json, '01[016789]-?\d{3,4}-?\d{4}|@example\.com');
-- 지연(NFR-01)
SELECT approx_percentile(to_unixtime(ingest_ts) - to_unixtime(source_ts), 0.95) FROM bronze.cdc_events
WHERE ingest_ts > now() - interval '1' hour;
```

F-04 훈련: 잘못된 바이트를 `cdc.mysql.commerce.orders` 에 1건 쓰고 → 잡이 계속 돌고 `dlq.ingest` 에 1건이 생기는지 확인.

## 완료 기준

- 생성기 가동 중 Bronze 3개 테이블에 행이 쌓이고, 평문 패턴 검사 0건.
- 독약 메시지가 DLQ 로 가고 정상 처리량이 유지된다.
